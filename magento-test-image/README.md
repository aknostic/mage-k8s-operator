# magento-test-image — reference image for envvars mode

A working Mage-OS 2.4.8-p4 image that satisfies the contract in
[`docs/image-contract.md`](../docs/image-contract.md). Fork this for
your own customer image; it is not a production image — see "Known
simplifications" below.

The Dockerfile started as a fork of the Dockerfile in Click & Mortar's
[magento-kubernetes](https://github.com/ClickAndMortar/magento-kubernetes)
(MIT license) and has since been largely rewritten. The `MAGENTO_*`
env var naming read by `env.php` follows their documentation.

## Build

```
docker build -t mage-operator/magento-reference:2.4.8 magento-test-image/
kind load docker-image mage-operator/magento-reference:2.4.8 --name mage-operator-dev
```

First build takes 20–30 minutes: composer pulls ~600 packages,
`setup:di:compile` is CPU-bound, and `setup:static-content:deploy`
generates assets for admin + frontend themes. Subsequent builds cache
everything until the composer layer or build args change.

## What's in the image

- Magento 2.4.8-p4 installed via `mirror.mage-os.org` (no Adobe
  Marketplace auth required).
- All modules enabled (`bin/magento module:enable --all`).
- DI classes compiled (`setup:di:compile`).
- Static assets deployed (`setup:static-content:deploy`) for admin
  and frontend themes in `STATIC_LOCALES` (default `en_US`).
  `MAGE_MODE=production` 404s missing static files — developer mode
  lazy-generates, production does not.
- `pub/static/deployed_version.txt` pinned to `CONTENT_VERSION` so
  scaled replicas serve consistent cache-busting URL segments.
- Canonical `env.php` (this directory's `env.php`, copied to
  `app/etc/env.php`) reads every config value from the operator's
  env var namespace — see `docs/image-contract.md`.
- nginx + php-fpm co-hosted via supervisord, listening on `:8080`.
- `msmtp` + `msmtp-mta` installed; `/usr/sbin/sendmail` routes to
  `msmtp` so Magento's `Mail\Transport` sends via SMTP. Runtime
  config at `/etc/msmtprc` is generated by `entrypoint.sh` from
  `SMTP_*` env vars on every pod start — see `docs/internals/local-smtp.md`.
- Required PHP extensions: `bcmath ftp gd intl opcache pdo_mysql
  soap sockets xsl zip` plus `sodium` from the upstream PHP image.

### Build-time tuning

```
docker build \
  --build-arg STATIC_LOCALES="en_US de_DE fr_FR" \
  --build-arg CONTENT_VERSION="$(git rev-parse --short HEAD)" \
  -t my-magento:2.4.8 magento-test-image/
```

`STATIC_LOCALES` is space-separated. Each additional locale adds ~1
minute to the build and ~30-80 MB to the image.

## Known simplifications (read before forking for production)

1. **Single-container nginx + php-fpm.** Production shape is a sidecar
   nginx container alongside php-fpm — better resource control and
   cleaner graceful-shutdown semantics. The reference image combines
   them via supervisord to keep the pod-shape minimal.
2. **Static assets baked at build time, not served from a CDN.** Real
   production deploys offload `/static/` and `/media/` to S3 + a CDN
   so pods don't carry 200-500 MB of theme assets each. Tracked as
   follow-up operator scope alongside `ensureMedia` for S3.
3. **No custom modules, themes, or extensions.** Bare Mage-OS.
4. **No `setup:install`.** A fresh store must run `setup:install`
   against the env var namespace before the admin UI serves —
   `ensureBootstrap` will automate this; until then use
   `config/samples/bootstrap-install-job.yaml`.
5. **No healthcheck probes.** Kubernetes default liveness/readiness
   probes work for dev. Production should define a real
   `/health_check.php` liveness and a startup probe.
6. **Runs processes as `www-data`.** Fine for dev; production
   deployments should add a `runAsNonRoot: true` + `runAsUser` under
   `securityContext`.
7. **2FA modules enabled by default.** Magento 2.4.x mandates 2FA for
   admin login and gates setup on email delivery. See
   `docs/internals/local-smtp.md` for configuring SMTP; customers who want to
   disable 2FA entirely run `bin/magento module:disable
   Magento_TwoFactorAuth Magento_AdminAdobeImsTwoFactorAuth`
   followed by `setup:upgrade` in the image's build.

## Files

| File              | Purpose                                                                                    |
|-------------------|--------------------------------------------------------------------------------------------|
| `Dockerfile`      | Multi-stage build (composer + di:compile + SCD in stage 1, runtime in stage 2).            |
| `env.php`         | Canonical envvars-mode env.php. Copied into the image at `app/etc/env.php`.                |
| `nginx.conf`      | Minimal Magento-aware nginx config (pruned from upstream `nginx.conf.sample`).             |
| `supervisord.conf`| Orchestrates nginx + php-fpm as a single PID-1 supervisor.                                 |
| `php-fpm.conf`    | TCP listener for the single-container case; `clear_env=no` so envFrom vars reach PHP.      |
| `seed-scopes.php` | Build-time helper: seeds `app/etc/config.php` scopes so SCD can run without a DB.          |
| `entrypoint.sh`   | Writes `/etc/msmtprc` from `SMTP_*` env vars, then execs the CMD (supervisord).            |
